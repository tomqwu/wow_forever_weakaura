# ForeverHUD implementation and reference notes

Version 0.3.3 implements the numbered work in [feature-parity-plan.md](feature-parity-plan.md). The reference inventory and work log distinguish source facts, ForeverHUD adaptations, mocks and outstanding game-client checks. Only the Warrior runtime source was supplied; the other eight class plans are original adaptations.

## Identity and selection

`src/catalog.py` declares candidates, school plans, original-equivalent Warrior stages and verified upkeep families. `scripts/build.py` generates the import and the companion's `Catalog.lua`; neither a seed nor a learning level proves training.

`Discovery.lua` scans actual learned spellbook entries outside combat. It matches localized names, complete configured ranks and learned bases/overrides, preferring the highest learned level independent of spellbook order. Missing, restricted and question-mark metadata fail closed. Proc aura IDs can qualify through learned native CDM identities without being castable spellbook actions. Learned passives cannot become action slots. Documented spell/talent/equipment/data events coalesce; disable/world leave cancels discovery and clears flags.

`Selection.lua` defaults to Forever mode. Discovery reads the same public data provider as the native manager, including saved category placement and order; the category-set API supplies defaults if the provider is unavailable. Only learned, resolved, non-invisible identities qualify. Since 0.6.0 the player's own category split decides the side: up to four Essential (damage) entries fill the left wing over Health, and up to four Utility entries fill the right wing over the resource bar (empty when the utility module is off). Each uses a native CDM identity selection inside an ordinary dynamic wing. Further entries overflow to the native rows. The native Show On Cooldown filter excludes GCD-only feedback; source category membership is not treated as evidence of a real cooldown. Dynamic groups compact shown clones without helper inspection of cooldown values. Stable legacy slot-group UIDs remain, with positional fallback for v0.3.2 imports until that class is updated. FA owns every clone and its restricted data. Additional rows use a native dynamic-group custom sort based only on public clone identity ranks, because multi-entry pickers otherwise sort by numeric entry ID. A native wrapper regression verifies that no protected state is read. Additional Essential entries use the same real-cooldown-only filter; Utility and equipped items have separate on-cooldown rows. Hidden entries stay out. Native layout edits refresh outside combat; empty login data has bounded settling retries. No spells are inserted merely to fill space. An unavailable CDM can fall back to learned plans; a known empty Essential list stays empty.

Optional Class plan mode chooses up to four attack/heal slots left and four cooldown/support slots right (swapped in 0.6.0 to match the damage-left rule), with ordered fallbacks and no duplicate learned identity. Warrior has the source's Leveling, ArmsEarly/Arms, FuryEarly/Fury and Protection plans, plus Cleave preference. Invested native talent-tree points choose a school; controls also allow manual selection. Druid form changes can reuse cached learned identities and update ordinary spell slots in combat, without rescanning spellbooks/CDM or changing root ancestry.

Unused learned combat skills occupy smaller on-cooldown offense/control/defense groups. Native CDM entries beyond these visible candidates feed a native cooldown clone row. Additional native tracked buffs/bars feed player-effect clones, including native stack/counter rendering. Preparation spells are excluded. Synchronization changes only ForeverHUD's CDM templates through the public FA API, outside combat, and skips unchanged selections. All descendants retain class and module eligibility flags; disabled modules unload their trackers.

## Native combat boundary and the placeholder fix

Aura presence, ownership, duration, stacks, resources, cooldowns, usability, range, casts, swings, totems and coatings belong to ForeverAuras' built-in triggers. Fixed Aura (Modern) slots never depend on helper scans of private aura-button visibility. Ordinary CDM clones use FA's own CDM renderer. There is no combat-log inference or guessed ability timer.

The v0.2.0 placeholder defect was a misplaced setting: FA reads **`display.triggers.secretFallback`**, not `display.secretFallback`. With the old layout, `SecretAuraSingle.FoundFollow` selected the always-true custom gate as a fallback when an aura was absent. The corrected import explicitly selects `none`; a regression executes the actual FA selector for both configurations. A general schema pass alone did not catch this semantic bug. A full top-level reimport is required to update existing saved aura configurations.

Warrior reminders use native missing/remaining-time filters for Rend and Battle Shout. Verified Intellect/Fortitude/Mark families have equivalent native upkeep reminders. Unknown Warlock armor never becomes a fabricated missing warning. Other class player effects, shields, aspects, blessings and weapon coatings show native observed states.

## State, motion and coordinates

Idle leaves the emblem while primary/resource assemblies fold. A readable living attackable target opens them. Optional combat-entry expansion is an explicit ForeverHUD extension; the supplied unfold predicate itself checked a hostile target. Combat events start opening/closing immediately using the event-confirmed state. Combat exit retains the independent hostile-target/inspection opening condition; otherwise it begins folding without a hold. Target loss alone starts a five-second close timer; reacquisition or combat entry cancels it. A center click pins inspection and a second click folds immediately out of combat, including with the same target. The manual fold clears on new target/combat/lifecycle edges; slash/settings inspection remains temporary. Casts and valid effects keep independent visibility rules.

Ordinary FA regions use native translation/alpha groups: the class-plan slots retain 65ms forward/reverse stagger and 280ms smoothstep; native cooldown wings slide as assemblies with native child reflow. The transition is approximately 500ms. Reversal samples the current trajectory. Layout/root-show/late-binding callbacks reconcile without resetting a running transition; late entries start from the opposite baseline and extend bounded cleanup. Resources remain visible sliding open and fade closed. No continuous Lua frame loop runs. Death/loading/world leave, editor restoration and disable stop or silently reconcile motion. Native aura-button lifetimes/animations remain client-owned.

`ForeverHUDAnchor` owns the root position in UIParent units. Outside combat, the companion explicitly repairs a root that FA created before the anchor was available. Scale applies to the imported root, not the saved position anchor. New/reset position is `(0,-160)`; existing coordinates survive upgrades. Overall preference/root ancestry edits queue in combat. A position-only reset preserves every other preference.

At 100% scale: seal 104×104 at `(0,13)`; chassis 512×128 at `(0,20)`; health/resource 180×13 at `(±138,13)`; main icons 40×40 at y=52, x=±(83+47×visibleIndex). Since 0.7.0 every row is centred on its own bar (x=±138) and grows both ways ([0.7 design](hud-design-0.7.md)). The DoT and buff rails at y=40 are ForeverAuras Modern Aura Groups (`blizzardFlow`, `CENTER_HORIZONTAL`), with members at offset 0. The Essential and Utility cradles at y=80 are centred dynamic wings placed at ±138 by `Selection.lua`, and class-plan icons use `S.Centred`. Native tracked buffs are centred at (138,116). Weapon coatings are fixed just past the resource bar. The positions below describe 0.6.2 where not superseded. Since 0.6.2 every row follows damage left, everything else right. The player's own buffs (plus Warrior Battle Shout reminders and weapon coatings) form the mirror row at y=40 over the resource bar, from x=60 rightwards. Native buffs grow right from (83,116). Essential overflow sits at (-138,-110), Utility and item overflow at (138,-57) and (138,-130), totems at y=-157. The Warrior Rend reminder takes the next DoT slot, procs sit at y=-23 under Health, and class-plan rows are Offense -160, Control 0, Defense 160. Since 0.6.1 target effects (DoTs) form a fixed 24px row at y=40, seated on the frame over the Health bar (from x=-60 leftwards in 26px steps, within the bar's -228..-48 span), and the main icon wings sit at y=80 above it; tracked bars sit at x=-410. Secondary categories use centered four-column grids at y=-57, swings y=-153, combo bar y=-155, cast y=-178 and additional native cooldowns y=-214. Modern player effects stay fixed; native CDM player effects have a separate row. Actual client spacing/stacking remains an acceptance check.

## Resources, casting, effects and sound

Native numeric rules hide zero countdowns, show tenths below one second, round seconds up, use minutes/seconds and urgency colors. Secondary countdowns sit below icons; prior formatting/points restore when disabled. Health/current resource text has integer precision. Health uses crimson, pet health a muted crimson, mana blue, energy/combo points gold, rage orange and focus amber. Artwork retains class colors. Main power starts neutral; native `powertype` conditions choose its color, including Druid form changes and neutral fallback for unknown identities. Localized role labels and native combo current/maximum text make color optional for identification; the helper reads only public resource identity, never amounts. Original geometric 480-frame, eight-second inward flow accents retain the native foreground progress masks. Actual off-hand equipment determines single/dual Warrior swings; manual Dual cannot invent a weapon. Hunter melee/ranged swings, native combo points, carried shards, pets and totem slots retain their actual client sources.

Casting is an explicit Default/ForeverHUD/Both display choice. The game bar is the default; legacy overlapping defaults migrate to it, while explicit previous ForeverHUD suppression remains. Module/legacy-switch edits normalize atomically into that choice, including combat-deferred changes. Suppression requires the native ForeverHUD cast aura to be loaded and restores the game bar when disabled/unavailable. `ForeverHUD.casting.Acquire(owner)` / `Release(owner)` support cooperative ownership. The implementation preserves Blizzard scripts/events, watches late bars and setters, and restores the latest external show request on final release. It cannot identify a foreign private owner that bypasses all setters/ownership interfaces. Completion decoration requires a matching observed start and successful cast; failed/interrupted casts cancel it, including channel-stop races.

Native modern-aura Start/Main settings supply low/blood/eyes/medium/major/defensive effect release/sustain. FA computes actual frame levels from **controlled-child order**: layers ascend in priority inside the Frame section, behind the seal and all later sections' bars/icons. Resource intensity uses native Power conditions and FA's own curve path, including restricted values. Ordinary cast/real-swing accents have a master switch, bounded attachment retries and cleanup. Resource and cast hosts attach independently; disabling one module stops its decorations without blocking the other. Native resource trim requires Resources eligibility. Reimports reuse owned frames and defer parent changes in combat. An observed cast stop cancels the loop immediately; a later matching success may still pulse.

Original PCM chimes replace the private reference's MP3 voice recordings. Ready alerts are learned/native-event driven, combat-qualified and scheduled with 60ms coalescing, priority, two-second deduplication, four-second TTL and one-second startup suppression. Queue timing uses the known lengths of our own audio, never an estimated ability duration. Buff activation sounds register with native aura Added; two no-self-buff Warrior shouts use actual successful casts. Native Added playback is client-owned, as in the source; it is not a Lua aura callback and cannot be routed through a fabricated aura-state queue.

Long-duration upkeep is a separate Maintenance buffs module, in a 20px side group at x=286/y=13, growing right beyond the resource bar (left side before 0.6.0). The stable Warlock Demon armor display moves there and hides its long-duration number; it still shows only a native observed active buff, never an inferred missing state. Since 0.9.0 spell suggestions sit in a fixed row (module `suggest`), in priority order. Since 0.10.0 every class has one list per spec (`SUGGESTIONS` in `scripts/build.py`, at most five rules so the row stays over Health). Each display carries its `spec` in the catalog. `Selection.SuggestSpec` picks the current school, or `Leveling` when the class has that list, and `Selection.Allowed` loads only that list's flags. Rule kinds are `curve`, `missing`, `buff` (own buff missing), `active` and `ready` (native Action Usable). Since 0.12.0 every row shares one spine from the seal. The DoT row and the class buff row are Modern Aura Groups growing `LEFT` and `RIGHT`, with their first icon's inner edge at x=±52 (group at ±66). The Core native buff row is a dynamic group growing `RIGHT` from x=66; a dynamic group centres its first icon on the origin. The native cooldown wings grow `LEFT` and `RIGHT` from x=±72, placed by the companion. Class-plan slots step 47 px outward from ±72 (`Selection.FromSeal`). Drawn grooves (media `groove`, a stand-in for the painted `rail-groove`) sit in the Frame over the chassis, 184 px wide from the seal edge: one under each rim row at y=40, and a cradle under the suggestion row at y=74. They are hidden while folded. Since 0.11.0 the actions form a Modern Aura Group growing `LEFT` (spacing 4) whose lead slot's right edge is at x=-52, so visible actions close up and the slot by the seal is the top one. ForeverAuras starts a legacy LEFT row at the first shown member's right edge; every member sits at the group origin, so the start is the same for every spec. Threshold cues (`curve`) can't join the row because they are shown at zero opacity until the curve fires. They live in `Suggest cues`: player mana at (218, -28) and pet health at (-218, -28), both 22 px, and target execute at (-212, 74), the row's fifth slot, so a list with an execute cue has at most four actions. A rule's size is per rule, not per slot, so the lead slot is marked by position only. The Warlock `Leveling` list keeps the 0.9 display IDs. Since 0.9.6 the row is on the damage side, centred over Health at x=-138, y=74: 4 px above the 28 px DoT row. Since 0.9.7 the row never moves. For a class with suggestions turned on, the companion raises the left (attack) cooldown wing by 34 px instead, so its 40 px icons, centred at y=114, clear the row. Those icons may appear only while on cooldown. Each one is a native check:
- **Life Tap and Health Funnel:** a Power or Health curve sets alpha (one protected curve per display, so rules can't be combined).
- **Corruption and Immolate:** Show On Missing on the target, gated by `E.SuggestTarget()` (combat and a living hostile target).
- **Shadow Trance:** the aura is active; eligible once Nightfall is learned.

The row gives way to the retracted tray. Since 0.8.1 a buff covered by reminders has no active icon: Demon armor, Arcane Intellect, Fortitude and Mark of the Wild appear only when missing or expiring. Buffs without reminders keep their active icon. Since 0.7.3 Warlocks also get the native upkeep reminders the other classes use: Show On: Aura(s) Missing, and Remaining Time ≤ 15 s, across Demon Skin, Demon Armor and Fel Armor. The client decides both states, so this is still not inferred. Native buff overflow excludes represented maintenance families by identities and localized metadata. Class-caption IDs remain stable empty displays.

New generated callbacks require the stable `importAPI = 1` boundary. The companion retains `E.version = "0.3.2"` for the historical v0.3.2 callback guard while reporting its current `releaseVersion`, allowing independent class updates. A newer import with an older/missing in-memory helper fails closed and each class's `Class name` display prints one localized reload instruction. Groups carry no custom actions: ForeverAuras compiles custom actions only for non-group displays, so the companion bind lives on `Class name` and each native wing's layout bind on its entry icons. Tests execute every generated bridge callback against missing/old helpers.

Native Tracked Bars can remain visible in the game's UI: leave FA's global Hide Blizzard's CDM off and keep all native viewers Always. Native viewer OnHide unregisters update events, so Hidden is not an opacity-only alternative. To avoid duplicate displays, choose the native icons and disable the corresponding ForeverHUD modules, or use ForeverHUD's optional bars with FA global opacity hiding. FA does not supply per-viewer opacity hiding; retaining native bars alongside ForeverHUD icons may retain duplicate native icons. The optional, off-by-default ForeverHUD trackedBars module uses a native Blizzard CDM Buff aurabar stack on the right. Its selections follow the native TrackedBar category, including target effects and player procs. Native CDMAuraProgress owns restricted progress and text; helpers never reconstruct DoT durations. When enabled, those entries leave the generic native icon overflow to avoid duplicating the same row; the existing icon fallback is retained when the optional bars are off. CDM global hide remains the user's FA setting, not a companion-owned mutation.

## Core and per-class packaging

Since 0.5.0 the displays every class shares live in one **`ForeverHUD | Core`** group: health, the current resource, the cast bar, the native CDM rows (overflow cooldowns, utility, items), native player effects and the tracked bars. Core displays load for all nine classes (FA's multi-select class load) behind `FOREVERHUD_CORE_<module>` load flags, which the companion sets from the current class's preferences. Their gate and style calls pass `CORE`, which the helper resolves to the current class. The Core cast bar takes the class accent from the helper (`E.Tint`), so one Core serves every class. Class groups keep their spells, effects, art, pet health and class extras.

Each import is its own root with independent frame levels (FA numbers levels from 0 per root). Class art textures therefore draw in the LOW strata while everything else inherits the anchor's strata, keeping Core bars above the chassis and seal without relying on cross-root level order.

The combined import (root `ForeverHUD`) holds the Core and all nine classes. `class_import` exports the Core or one class group as its root, with a stable UID, no external parent, only that group's descendants, and the companion anchor (`SELECTFRAME ForeverHUDAnchor`). The partial export never contains the shared root: FA's default Remove Obsolete Auras option therefore cannot interpret other classes as removed. Native updates retain the target's existing parent; fresh imports stay standalone. The companion resolves the standalone class and Core roots, or the existing combined root, from public aura metadata and applies the same saved anchor, scale and opacity to each outside combat. Runtime lookups go through `E.DisplayID`, which maps shared sections to the Core and everything else to the class group.

A 0.4 class group still contains displays that moved to the Core under new names; with both installed they would draw twice. A read-only login check warns once while the class group still has a `Health` child, and `/fhud install` waits until it is deleted.

Binding coalesces and waits for the public `IsImporting` state to end, so the temporary parent removal in native import phase 1 does not select the wrong root. The retry runs every 0.1 s for two minutes, then every second while the import continues, and is cancelled on world leave. Nothing in the companion mutates displays during an import: root layout, CDM selection sync (`api.Add`), late ability layout and the root show/hide motion hooks all defer to that retry, and discovery defers its own data updates. This is UI lifecycle handling, not an inferred combat timer.

## Bundled imports (companion install/update)

The addon carries the Core and every class import in the generated `Catalog.lua` (`E.bundledImports`, keyed `CORE` and by class token), so the TOC file list is unchanged and a `/reload` is enough after an upgrade. At `ADDON_LOADED` (before ForeverAuras' login announcement), the companion registers the Core and only the current class through ForeverAuras' public `AddCompanionData`. For each it always registers a `slugs` entry, and FA lists an update when an installed display's `url` carries an older build. It adds a `stash` entry ("ready to install") only when that group is missing or predates update tags. Clicking either calls FA's own `Import`, which shows the Import/Update window and matches an existing group by UID. FA runs one import at a time, so `/fhud install` opens the first group that is missing or older (Core, then class) and says to run it again for the next. The companion never writes aura data or SavedVariables.

Every display's `url` is `https://wago.io/forever-hud-<core|class>/<build>`, with build = major·10000 + minor·100 + patch (0.5.0 → 500). This is FA's expected format; FA only parses it and never fetches anything. The combined root has no tag.

A read-only scan of `ForeverAurasSaved.displays` counts the Core's and this class's displays that have no parent, excluding each root itself. A non-zero count means an earlier import stopped part way: the companion prints one localized warning per session, and `/fhud install` refuses to import over it unless given `force`, because FA would meet those UIDs outside the matched group.

## Aura structure

The Core's direct children are **Resources** (health, power), **Native rows** (CDM overflow/utility/items), **Native auras** (native player effects, tracked bars) and the **Cast** bar. Each class group's direct children are organising sections only, in draw order: **Frame** (chassis, runes, FX layers, seal, caption), **Resources** (pet health and class extras, only when the class has them), **Primary**, **Utility**, **Auras** (target/player effects, maintenance, reminders, weapon coatings), **Nameplates** and **Alerts**. Section groups sit at `(0,0)`, so child coordinates are unchanged; FA assigns frame levels depth-first in list order, so FX inside Frame stays behind the seal, and the LOW art strata keeps the whole Frame below other displays. Depth below the class root is at most three (Primary → native wing → entry). No empty placeholder groups are generated: the v0.3.2 "Native N" slot groups and empty Maintenance rows are gone. Display IDs/UIDs are unchanged, and FA's Update treats child offsets as Group Arrangement (default on), so an Update moves existing displays into their sections, including the Warrior proc cues' Primary-relative offset. The generator asserts that no loose display remains at a class root, and none at the Core root except the cast bar.

Every class export is independently codec-verified, checked for a closed graph, preserved IDs/load flags, disjoint class scope, complete union with the combined graph and matching ZIP bytes. A generated manifest records characters, bytes, counts, root UID and SHA-256. Actual multi-class installation/update UI acceptance remains pending.

## Artwork and evidence

The AI-painted masters and exact prompts remain in `assets/ai/`. Own emblems/frame/borders are reused; no Guos media, scripts or voice files are bundled. Small geometric flow/rune accents remain SVG. Runtime textures are power-of-two RGBA TGA; audio is original mono PCM WAV.

The HTML/PNG previews show explicit sample learned lists, auras and values. They do not run WoW or establish protected-widget behavior. Actual FA validators/fallback/curve/condition code runs in a mocked client environment. Live spellbook comparison, combat taint, physical position, native sound timing and normal logout persistence remain required; see [validation.md](validation.md).
